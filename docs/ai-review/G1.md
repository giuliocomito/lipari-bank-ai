# AI Code Review: Giorno 1

Il codice proviene dal Code Blueprint; l'ho integrato nel progetto con l'aiuto di un assistente
AI, che ha scritto anche il README e l'estensione. La revisione segue le quattro voci previste
per questa giornata.

| # | voce | rilievo | decisione |
|---|---|---|---|
| 1 | dipendenze | Tutte le dipendenze dichiarate sono effettivamente usate: l'applicazione usa `fastapi`, `uvicorn[standard]` e `pydantic-settings`, mentre gli strumenti di controllo e i test usano `ruff`, `mypy`, `pytest`, `pytest-asyncio` e `httpx`. | nessuna modifica |
| 2 | dipendenze | Il pacchetto `uvicorn[standard]` installa anche `websockets` e `httptools`, che oggi non sono necessari. | non corretto: la variante standard di uvicorn installa anche `watchfiles`, da cui dipende l'opzione `--reload` indicata nel README, e fornisce un server più veloce in produzione. Eliminare uno per uno i pacchetti superflui richiederebbe una manutenzione più onerosa del peso che si risparmierebbe. |
| 3 | segreti | Il codice non contiene alcuna chiave: i segreti provengono dall'ambiente o dal file `.env`, che `.gitignore` esclude dal repository e che non è mai entrato in un commit. Ho generato il segreto JWT locale con `secrets.token_urlsafe(48)` e l'ho salvato soltanto nel `.env`. | nessuna modifica |
| 4 | segreti | Il file `conftest.py` contiene in chiaro il valore `segreto-dei-test-lungo-almeno-trentadue-caratteri`. | non corretto: si tratta di un valore destinato ai test, che `setdefault` imposta soltanto quando l'ambiente non ne fornisce uno e che non dà accesso ad alcuna risorsa. In produzione questo valore verrebbe respinto dall'estensione «produzione che non accetta comodità». |
| 5 | tipi | Il comando `uv run mypy src` termina senza errori in modalità strict, con il plugin di Pydantic, e ogni funzione dell'applicazione è annotata con i tipi. | nessuna modifica |
| 6 | tipi | I test non sono tipizzati per intero, perché ruff ignora le regole `ANN001` e `ANN201` nella cartella `tests/`. | non corretto oggi: la consegna rinvia al Giorno 7 la regola di mypy che riguarda i test. |
| 7 | secondo sviluppatore | Il README creato da `uv init` era vuoto, sicché chi clonava il repository non sapeva come installare il progetto né che fosse necessario un `JWT_SECRET`. | corretto: il README spiega ora l'installazione passo per passo, fino alla prima risposta dell'endpoint `/health`, e riporta il tempo impiegato da una ricostruzione completa del progetto a partire da zero. |
| 8 | secondo sviluppatore | L'installazione avveniva con `uv sync`, che può risolvere di nuovo le versioni delle dipendenze. | corretto: ora si usa `uv sync --locked`, che installa le versioni fissate nel lockfile oppure si interrompe con un errore. |
| 9 | secondo sviluppatore | In Windows PowerShell 5.1 `curl` è un alias di `Invoke-WebRequest`, perciò il comando indicato nel README non produceva il risultato atteso. | corretto: il README contiene ora una nota che invita a usare `curl.exe`. |
| 10 | secondo sviluppatore | A ogni esecuzione `pytest` stampava un avviso di deprecazione di pytest-asyncio, e chi clona il repository non può sapere se l'avviso segnali un problema. | corretto: l'impostazione `asyncio_default_fixture_loop_scope = "function"` è stata aggiunta nel `pyproject.toml`. |
| 11 | secondo sviluppatore | Il file `.env.example` elencava soltanto i nomi delle variabili, senza indicare quali fossero obbligatorie né come si dovesse generare il segreto. | corretto: ogni riga è ora accompagnata da un commento, e un test verifica che il file resti allineato alla classe `Settings`. |
